# Interface localization

Currywurst uses the Chrome/Edge extension localization API, with `default_locale` set to `en` in the manifest. Only English ships initially. This localizes the interface; German–English lookup directions, German word forms, English meanings, IPA, recordings, and saved vocabulary retain their original data.

The English source catalog is [_locales/en/messages.json](../_locales/en/messages.json). [i18n.ts](../src/shared/i18n.ts) provides typed message lookup, grammar-label mappings, and UI error formatting. React renders popup messages and dictionary content as text. Set document language, direction, and title at startup; catalog messages should contain plain text, not HTML.

## Add a language

1. Create `_locales/<supported-locale>/messages.json`, using a [supported browser locale](https://developer.chrome.com/docs/extensions/reference/api/i18n#locales). For example, a German catalog would use `_locales/de/messages.json`.
2. Copy the English catalog and translate its `message` values. Keep message keys unchanged. A partial catalog may omit untranslated messages; the browser falls back to English for those messages.
3. Set `ui_locale` to the catalog's language tag and `ui_direction` to `ltr` or `rtl`. Review layout and text expansion when adding a language, especially for a right-to-left interface.
4. Preserve named placeholders such as `$WORD$`, `$COUNT$`, and `$TYPE$`, together with their `placeholders` definitions. Placeholders can be reordered within a translated sentence, but their definitions must continue to reference the same arguments. The context-menu message must retain `%s`, which the browser replaces with the selected text.
5. Keep Currywurst and source-provider names intact. The German footer quote intentionally remains German. Grammar identifiers, source words, language codes used for pronunciation, and stored vocabulary must not be translated in application logic.
6. Run the checks below, then reload the unpacked extension in Chrome and Edge with the target browser interface language. Inspect loading/error states, tabs, saved words, audio labels, keyboard navigation, and narrow table layouts.

```sh
npm run check
npm run test:extension
```

The release script includes every locale's `messages.json` file and requires the default catalog. No new permissions or translation-service requests are needed for interface localization.

## Add an interface string

Add a stable, descriptive key to the English catalog. Use `t("key", substitutions)` in JSX text and attributes such as `title` and `aria-label`. `MessageKey` is derived from the English catalog, so unknown application message keys fail type checking. Keep icons and counters as separate JSX children. Avoid HTML-string rendering and post-render DOM localization in React components.

Known dictionary grammar labels are mapped in `GRAMMAR_MESSAGES`; map additional source labels there rather than changing parser data. Stored-word errors carry a `messageKey` through the background worker and are localized by the popup. Unknown browser or network errors retain their supplied message.

Chrome's [localization message format](https://developer.chrome.com/docs/extensions/how-to/ui/localization-message-formats) documents message catalogs and substitutions.
